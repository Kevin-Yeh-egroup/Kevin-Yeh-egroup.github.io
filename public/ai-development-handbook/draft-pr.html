開一張審查草稿（Draft PR）

PR 是請隊友看這批修改的頁面。Draft 代表草稿。如果你用 LOCAL-1 練習，先照常擬草稿。要正式送出時，請帶教人提供 GitHub 練習專案，再用實際工單、分支及已確認的預覽接續。

  1. 負責人確認預覽
  2. 取得送出授權
  3. 推送分支，開 Draft PR
  4. 後｜PR 頁面看得到改動、檢查結果與證據
  1. 貼「備 PR 草稿」，先看文字內容對不對。
  2. 負責人確認預覽並授權後，才貼「授權後送出」。
  3. 打開 PR 網址，核對目標分支、提交、差異與自動檢查（CI）。
  4. 證據還沒補齊時，維持 Draft。
備 PR 草稿，不對外（貼給 Codex）
看完整指令
請依目前分支的 commit 和 Issue，擬一份 Draft PR 的標題與內文草稿，欄位為：關聯 Issue、改了什麼、使用者影響、驗證結果與未驗項目、驗收畫面與證據（逐項列出驗收條件、證據與對應提交）、希望 Reviewer 幫忙確認。只輸出文字草稿，不要 push，也不要在 GitHub 建立任何東西。
取得授權後再貼｜先填專案網址和分支
看完整指令
負責人已確認預覽，我授權在【填入練習專案網址】推送【填入分支】並建立 Draft PR。先核對目前的 GitHub 專案、分支、工單與確認過的 PR 內容。欄位沒填或資料對不上時停下來，告訴我哪裡不一致。完成後回報 PR 連結、目標分支、最新提交、檢查狀態、是否可合併，以及 PR 上的相關證據能不能打開。還在計算的項目標示待確認。

過關畫面 打開 PR 網址，目標分支、提交、差異和自動檢查都對得上；驗收畫面在 PR 裡打得開，而且對應最新的提交。

帶教備註

團隊規則示例：push 與開 PR 前先交預覽並取得對應確認，預設 Draft PR，標題用 [issue/<編號>] <摘要>。是否可合併仍在計算時標待確認；有衝突先處理再重新驗證。合併後應結束工單時，依專案規則使用 Closes #<編號>，否則用 Refs。也可以用瀏覽器在 Pull requests 頁手動建立，重點是選對 base 與 compare。
