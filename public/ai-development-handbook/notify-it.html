送審

通知 IT

讓對方打開 PR 一分鐘內就知道要幫忙看哪一點。前置條件：已有 PR，檢查與證據符合團隊要求。通知對象與管道以團隊設定卡為準；沒有發送授權時只準備通知稿，由你自己送出。

  1. 檢查與證據齊全
  2. 擬通知稿：連結、狀態、想問的一題
  3. 依設定卡的對象與管道送出
  4. 後｜對方知道要審什麼，意見留在 PR
  1. 貼「擬通知稿」，請 Codex 準備草稿。
  2. 對照團隊設定卡，填入對象與管道。
  3. 核對內容後由你送出，或在取得授權後請 Codex 協助。
  4. 收到審查意見，回到同一張 Issue 和 PR 修訂，重跑受影響的檢查。
擬通知稿（貼給 Codex）
看完整指令
請依目前的 PR 和 Issue，幫我擬一則給 IT／Reviewer 的通知稿，包含：PR 連結、Issue 連結、這次改了什麼、測試結果在 PR 的哪一段、PR 目前是 Draft 或 Ready、還在等什麼、希望對方確認的一個問題。對象與管道留空，我會依團隊設定卡填寫。只提供草稿，不要代我發送，也不要變更 PR 狀態。
通知訊息範本（自己填寫後送出）
看完整指令
嗨【IT／Reviewer】，想請你協助審查【PR 連結】對應【Issue 連結】。這次讓搜尋忽略關鍵字前後空白，測試結果在 PR 的「驗證」段落。請協助確認空查詢行為是否符合目前規則。PR 目前為【Draft／Ready】，尚待【如實填寫】。方便的話請把意見留在 PR，謝謝。

過關畫面 通知裡有 PR 連結、目前狀態，以及希望對方回答的一個問題。對方不用再回頭問你「要看什麼」。

帶教備註

轉為 Ready for review、指定 Reviewer 與發通知都是外部操作，依授權與團隊流程辦理；GitHub 上的指派和團隊通知各自依約定執行。團隊需要 IT 提前看 Draft 時，通知中寫清楚還在等哪些結果。合併與部署依團隊權限，不在新人練習範圍。畢業關卡三題：指得出修改在哪個分支、能示範失敗到通過、IT 一分鐘內知道要審什麼。
