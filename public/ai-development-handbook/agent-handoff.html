Agent 分工

兩個 AI 幫手一起工作時，同一時間只讓一個動手改檔案，另一個只看不改。這裡 Codex 是唯一寫入者，本機 Claude Code 做唯讀複核，由你手動把內容貼過去交棒。前置條件：已有一次存檔好的修改（「驗證並存檔」一課），本機 Claude Code 已依團隊允許的帳號與資料範圍安裝，並開在同一個專案資料夾。

  1. 你：指定 Codex 為唯一寫入者
  2. Codex：寫交棒單（輸入、產物、停止條件）
  3. 你：手動貼給本機 Claude Code
  4. Claude：唯讀複核，列出發現後停止
  5. 你：把發現貼回 Codex
  6. 後｜Codex 查證、修改、重跑測試
  1. 貼「準備交棒單」給 Codex，它寫完後會暫停修改。
  2. 在同一個專案開啟本機 Claude Code，貼「唯讀複核」，並把交棒單附在後面。
  3. 先看 Claude 回覆的資料夾與分支對不對，再看發現清單。
  4. 把發現清單附在「交回 Codex 查證」後面，貼回 Codex。
  5. 要改正式畫面時，改用「請 Claude 先畫稿」，稿件經負責人確認後才讓 Codex 實作。
準備交棒單（貼給 Codex）
看完整指令
請準備一份交棒單，讓我手動貼給本機 Claude Code 做唯讀複核。內容包含：專案與 Issue、分支與最新 commit、這次改了什麼、驗收條件、已跑的檢查與結果、希望對方特別留意的地方。並註明：此階段唯一寫入者是 Codex，Claude 只讀不改；輸入是本次 Issue 的差異與測試；產物是一份發現清單；停止條件是看完本次差異與測試就停。不要放入密鑰或個資。輸出交棒單後請暫停修改，等我把複核結果貼回來。
唯讀複核（貼給本機 Claude Code，後面附上交棒單）
看完整指令
請先回覆實際工作目錄、分支與已讀專案規則。這次只做唯讀複核：不要修改、建立或刪除任何檔案，也不要執行會改變工作區的指令。審查這次 Issue 的差異及測試，留意尚未涵蓋的輸入和可能改變的行為。每個發現附檔案位置、觀察依據及最小檢查方式，讓 Codex 複核。看完本次差異與測試就停下，輸出發現清單；沒有發現也請明說。

交棒單：
【貼上 Codex 準備的交棒單】
交回 Codex 查證（貼給 Codex，後面附上發現清單）
看完整指令
以下是本機 Claude 的唯讀複核結果。請逐項查證：成立的，說明依據並做最小修改、補上對應測試、重跑相關檢查；不成立的，說明原因。只處理本次 Issue 範圍內的項目，範圍外的列為後續建議。

複核結果：
【貼上 Claude 的發現清單】
正式畫面變更：請 Claude 先畫稿（貼給本機 Claude Code）
看完整指令
請先回覆目前目錄、分支、Issue、已讀的共用產品體驗標準與產出位置。沿用專案既有的品牌規範、設計 tokens 與正式元件，做一份實際可渲染的設計稿，呈現桌機與手機，以及輸入、結果、空結果、錯誤等適用狀態，使用假資料。這階段只寫入設計稿與指定產物，不修改正式程式。完成後告訴我怎麼打開稿件，並列出需要負責人確認的事項。找不到共用標準時請停下來告訴我，不要自行假設。
進階｜在 Codex 專案內試一次 Agent 分工
看完整指令
如果這個 Codex 環境支援子 Agent，我授權開一個唯讀子 Agent，獨立確認這次修改與既有測試有沒有漏掉重要情境。請給它專案路徑、工單、分支、要看的差異與驗收條件。它只回報檔案、依據和測試建議，完成一次複核就停。你是唯一能寫入程式的 Agent，收到結果後請查證並回報。若沒有子 Agent 功能，請輸出同樣的交棒單，我會把它貼給本機 Claude Code。

過關畫面 任何時刻只有一個寫入者。Claude 的每個發現都對得到實際檔案位置；Codex 查證後重跑測試通過。交棒單寫明了輸入、產物與停止條件。

帶教備註

手動交棒（複製貼上）就足夠，不需要自動串接；沒有需求來源的自動化不要先做。分工原則：Codex 負責實作、實測與存檔，Claude 的複核與設計提案分開記錄，分歧與不採用的原因也留下。正式 UI 的順序固定為：Claude 產出實際可渲染稿、負責人打開確認、Codex 才實作、最後逐項對稿。設計稿的進階內容依共用產品體驗標準補齊：利害關係人關係圖（區分已確認與待確認角色）、自動化泳道圖（全自動、半自動、人工）、畫面故事板、情境腳本與測試覆蓋矩陣（測試層、斷言、假資料、證據與人工驗收責任），並說明希克、峰終、雅各布、預設效應、損失規避五項原則的適用判斷與覆蓋範圍。設計階段只能說「測試已規劃」，有執行證據才說「通過」。Claude 可使用的資料範圍與共用標準的位置，以團隊設定卡為準；尚未收到 Claude 回覆確認前，交接標為待完成。
